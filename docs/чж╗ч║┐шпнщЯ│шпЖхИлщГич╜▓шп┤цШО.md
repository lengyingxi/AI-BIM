# 离线语音识别部署说明

本机语音识别负责把麦克风的 PCM 直接转成文字，全程不出本机、不依赖任何云服务，
内网和断网环境都能用。本文说明当前用的引擎、怎么装到一台干净机器上、怎么换模型、出问题怎么查。

---

## 一、当前用的引擎

**sherpa-onnx + 流式 zipformer（中文多方言版）**

| 项目 | 说明 |
| --- | --- |
| 引擎 | [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0），纯 ONNX Runtime，**不依赖 torch** |
| 模型 | `sherpa-onnx-streaming-zipformer-multi-zh-hans-2023-12-12`（int8） |
| 体积 | 约 70 MB（encoder 70 MB + decoder 1.3 MB + joiner 1 MB + tokens） |
| 方式 | 流式，边说边出字；每 0.3 秒一包 PCM |
| 速度 | CPU 实时率 0.06（10 秒语音约 0.6 秒算完），比 vosk 小模型快 5 倍 |
| 兜底 | 没装 sherpa 的机器自动退回 vosk（`vosk-model-small-cn-0.22`），接口完全一样 |

### 为什么换掉 vosk

同一批语音（12 句运维口令，TTS 合成以便复现），两个引擎的对照：

| 指标 | sherpa-onnx zipformer | vosk small-cn |
| --- | --- | --- |
| 整句全对 | **11 / 12** | 9 / 12 |
| 平均字错率 | **0.6 %** | 7.9 % |
| 典型错法 | — | 往东→网综、往左→王座、往右→网友、机柜→接轨 |

vosk 的错集中在**方向词**上——恰好是这类语音指令里最不能错的部分，
所以体感上"很不准"。换成 sherpa 后方向词全部正确。

真实录音那 6 句（`tools/asr/*.wav`，含 18 秒连说两句的样本）：
识别层 5/6 逐字正确，剩下 1 句错 1 个字（挪→檬），语义层已兜住，实际可用 6/6。

## 二、两条识别通道

页面启动时先探 `/asr/health`：

- 本机能跑 → 走 **local**（sherpa/vosk），完全离线；
- 本机不能跑 → 走 **web**（浏览器自带 SpeechRecognition，要连 Google/微软云）；
- 都不可用 → 关掉麦克风按钮，只用文字输入。

两条路都按"说完停顿 1.4 秒"结算，不会挂在那里一直听。

识别结果不会直接执行，先过一遍 `web/js/nlp.js`：

1. `N.asrFix()` —— 同音字纠正（王座→往左、网综→往东、水浦→水泵、檬→挪…）；
2. `cnNum()` —— 中文数字转阿拉伯数字（一零一→101、一米二→1.2 米）；
3. `N.parse()` —— 抽意图 + 要素（设备/房间/方位/距离/尺寸）。

所以**识别层错一个字不等于指令会错**，语义层是最后一道闸。

## 三、装到一台干净机器上

### 1. Python 依赖

```bash
pip install sherpa-onnx numpy        # 必须
pip install vosk                      # 可选，只在没有 sherpa 时兜底
```

`sherpa-onnx` 是预编译 wheel，Windows / Linux / macOS 的 x86-64 都有，
不需要编译、不需要 CUDA。

### 2. 模型文件

目录结构必须是（文件名可以不同，但要能按前缀认出来）：

```
tools/asr/mzh/
├── tokens.txt
├── encoder-epoch-20-avg-1-chunk-16-left-128.int8.onnx
├── decoder-epoch-20-avg-1-chunk-16-left-128.int8.onnx
└── joiner-epoch-20-avg-1-chunk-16-left-128.int8.onnx
```

在线下载（GitHub 直连很慢，用 HF 镜像）：

```bash
R=k2-fsa/sherpa-onnx-streaming-zipformer-multi-zh-hans-2023-12-12
for f in tokens.txt \
         encoder-epoch-20-avg-1-chunk-16-left-128.int8.onnx \
         decoder-epoch-20-avg-1-chunk-16-left-128.int8.onnx \
         joiner-epoch-20-avg-1-chunk-16-left-128.int8.onnx; do
  curl -L -o "tools/asr/mzh/$f" "https://hf-mirror.com/$R/resolve/main/$f"
done
```

内网部署就把 `tools/asr/` 整个目录拷过去（70 MB 左右），
**不需要**在目标机上联网。

> 完整发布包（1 GB，含 fp32 + int8 全精度）在 GitHub Releases：
> `sherpa-onnx-streaming-zipformer-multi-zh-hans-2023-12-12.tar.bz2`。
> 只想省体积就用上面的 int8，精度几乎无损。

### 3. 启动

```bash
python tools/serve.py --port 8823 --key-file tools/.llm_key
```

启动日志里会有一行"模型加载完成"。确认：

```bash
curl http://127.0.0.1:8823/asr/health
# {"ok": true, "state": "ready", "engine": "sherpa-onnx", "model": "mzh", ...}
```

### 4. 自检

```bash
python tools/asrselftest.py     # 真实录音 6 句，走 /asr/* 流式接口
python tools/asrcmp.py          # 两个引擎横向对比（TTS 合成 12 句）
```

`asrselftest.py` 会把每句的**期望 / 识别 / 中间预览**都打出来，
逐字正确率和语义层兜底后的正确率分开报，一眼能看出问题出在哪一层。

## 四、换模型

放进 `tools/asr/` 下任意子目录，只要同时具备 `tokens.txt` 和
`encoder/decoder/joiner` 三个 `.onnx`，启动时会自动认出来（按目录名排序取第一个）。
多个模型并存时想看哪个生效，就看 `/asr/health` 返回的 `model` 字段。

也可以直接指定：

```bash
python tools/serve.py --asr-model /data/models/my-zh-model
```

**想更准、不在乎延迟**，可以换非流式的大模型（同一套 sherpa-onnx 接口，
`OfflineRecognizer`）；代价是必须等一句话说完才能出结果，
"边说边出字"的预览会没有。当前选择流式的理由：语音指令都很短，
用户需要看到"我说的话正在被正确听到"。

## 五、排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/asr/health` 返回 `state: "error"` | 依赖或模型缺 | 看 `err` 字段，它会直接说清缺哪一个 |
| `engine` 是 `vosk` 而不是 `sherpa-onnx` | 没装 sherpa-onnx 或模型目录不完整 | `pip install sherpa-onnx`，确认三个 onnx 都在 |
| 识别出的字带空格 | 结果里混了英文 | `asr_cn()` 里已处理：纯中文去空格，含英文保空格 |
| 说完没反应、也不结算 | 麦克风没采到声音 | 页面右下角电平条要有跳动；`--no-asr` 时走浏览器识别，需要联网 |
| 一直"没听清" | 环境噪声盖过人声 | 页面已开 `noiseSuppression`，仍不行就换近场麦克风 |
| 句子被截断 | 说话中间停顿超过 1.4 秒 | 这是刻意设计（短口令体验更好），连说时不要长停顿 |

## 六、涉及的文件

| 文件 | 作用 |
| --- | --- |
| `tools/serve.py` | `/asr/start`、`/asr/chunk`、`/asr/final`、`/asr/cancel`、`/asr/health`、`/asr/warm`；双引擎加载与切换 |
| `web/js/app.js` | 麦克风采集 → 16k 单声道 PCM → 0.3 秒一包上传；静音 1.4 秒结算；识别预览显示 |
| `web/js/nlp.js` | `asrFix` 同音纠错、中文数字转换、意图与要素抽取 |
| `tools/asrselftest.py` | 真实录音流式自检（逐字 + 语义层双口径） |
| `tools/asrcmp.py` | 两引擎横向对比（TTS 合成语料） |
| `tools/asr/` | 模型文件与测试音频 |
